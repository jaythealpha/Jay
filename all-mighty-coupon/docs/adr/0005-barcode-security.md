# ADR-0005: 바코드 보안 — 암호화 저장 + 해시 기반 중복 검사

- 상태: 채택됨 · **전 항목 구현됨 (M1–M2)** — 관리자 측 열람 차단 UI만 남음
- 날짜: 2026-08-06

## 결정

1. 바코드 **원문**은 서버에 AES-256-GCM으로 암호화해 `encryptedBarcode`에
   저장한다 (키: `BARCODE_ENCRYPTION_KEY`, 64-hex env) — 구현·테스트 완료
   (`apps/api/src/crypto/barcode-crypto.service.ts`, 저장 포맷
   base64(iv|authTag|ciphertext)).
2. 중복 검사·조회는 원문이 아니라 **정규화 SHA-256 해시**(`barcodeHash`)로만
   한다 — 구현·테스트 완료 (`@amc/barcode-utils`).
3. 원문은 일반 로그·분석 이벤트·목록 API 응답에 절대 포함하지 않는다 —
   로그 마스킹과 DTO 경계로 구현·테스트 완료.
4. 원문 열람은 전용 API로만(`GET /v1/coupons/:id/barcode`, 소유자 전용),
   열람 시 `BARCODE_VIEWED` 감사 이벤트를 남긴다 — 구현·테스트 완료(M2).
   모바일은 열람 값을 플랫폼 보안 저장소에만 캐시해 오프라인 표시를
   지원한다. 관리자 화면의 기본 열람 차단은 Admin 기능 구현 시 적용.

## 근거

바코드 원문은 곧 금전 가치다. 유출되면 제3자가 사용할 수 있으므로
비밀번호에 준해 다룬다. 해시 분리는 "중복 감지 기능"과 "원문 보호"를
동시에 만족시키는 표준 패턴이다.

## 정규화 규칙

공백·하이픈 제거 + 대문자화 후 해시 — 같은 쿠폰이 포맷 차이로 중복 통과하는
것을 막는다. 규칙 변경 시 기존 해시 재계산 마이그레이션이 필요하다.
