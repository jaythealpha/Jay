# Test Plan

API 단위 21개(바코드 암호화 3, 이미지 프로세서 3, 업로드 검증 4 포함),
API 통합 9개(인식 파이프라인 5: 추출·암호화·중복·검토→확정·INVALID·업로드

## 커버리지 목표

Domain logic ≥90%, Application service ≥80%, UI는 핵심 흐름 중심.
숫자를 채우기 위한 의미 없는 테스트 금지. 테스트를 통과시키기 위해 검증
로직을 약화하지 않는다.

## 통합 테스트 필수 흐름 (M1~M2에서 추가)

- 이미지 업로드 → 쿠폰 생성 → 분석 Job → 결과 저장 → 상태 업데이트 → 이벤트 기록
- 쿠폰 수정 → 상태 재계산 → 이벤트 기록 → 알림 재예약
- 사용 완료 → REDEEMED → 알림 취소 → 이벤트 기록
- 복구 → ACTIVE(재계산) → 알림 재예약 → 이벤트 기록

## E2E 최소 시나리오 (M2 목표)

1. 신규 사용자 첫 쿠폰 등록 → 2. 추출 결과 확인·저장 → 3. 쿠폰함 검색 →
2. 필터 → 5. 상세에서 바코드 열기 → 6. 사용 완료 → 7. 사용 완료 취소 →
3. 중복 이미지 등록 → 9. OCR 실패 후 직접 수정 → 10. 오프라인에서 쿠폰 열기
